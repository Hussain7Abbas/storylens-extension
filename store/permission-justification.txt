=== PERMISSION JUSTIFICATIONS (Chrome Web Store) ===
Copy each section below into the matching dashboard field (1,000 character limit each).

--- tabs justification ---

StoryLens uses the tabs permission to read the active tab’s URL so it can detect which web novel and chapter the user is reading. The background service worker maps that detected metadata to the tab ID so the popup can show the correct novel context. When the user edits keywords or replacements in the popup, StoryLens sends a refresh message to the active tab so highlights and text replacements update on the page without a manual reload. The tabs permission is also used to clean up cached per-tab data when a tab is closed and to target the active page when the user clicks Summarize.

--- storage justification ---

StoryLens uses chrome.storage.local to persist extension settings and state between sessions. This includes the user’s auth session token, optional desktop pairing token and model choice, onboarding completion status, analytics preference and random client ID, and offline sync metadata such as pending glossary changes waiting to upload and the list of novels downloaded for offline reading. Storage keeps these preferences and reference edits available across browser restarts.

--- alarms justification ---

StoryLens uses the alarms permission to run a periodic background sync every five minutes. When the user is online, this alarm uploads pending offline glossary changes (keywords, replacements, categories, and related edits) to the StoryLens API and updates the extension badge to reflect sync status. Alarms allow this work to happen reliably in the background without keeping the popup open, so user changes made while reading are saved even if the user closes the extension UI.

--- unlimitedStorage justification ---

StoryLens users may build large glossaries with many keywords, replacements, categories, and offline edits across multiple novels. The extension stores offline sync queues and related local state in chrome.storage.local, which can grow beyond Chrome’s default storage quota as pending changes accumulate. unlimitedStorage ensures that sync metadata and queued edits are not lost when a user maintains a large glossary or works offline for extended reading sessions.

--- Host permission justification ---

StoryLens needs access to web novel pages so its content script can locate chapter text and apply keyword highlights and replacements. Novel sites use many domains and URL structures, so the extension must run on reading pages the user opens. Chapter text is processed locally for those features. Only user-requested AI actions send relevant page content to an AI provider as explained in the listing and privacy policy.

StoryLens also needs host access to https://storylens-api.iscoded.com so the background service worker can sync the user’s novels, keywords, categories, replacements, and settings with the StoryLens backend over HTTPS.
When no desktop AI provider is configured, user-requested chapter-selector detection also sends the current page URL and HTML to this API for OpenRouter analysis. With desktop AI configured, detection uses the loopback Story Lens Client and the selected provider instead.

StoryLens also needs access to http://127.0.0.1/* so the background worker can contact the user’s paired desktop client. Requested summaries, keyword suggestions and chapter keyword extraction send relevant page or reference content to the local client and selected AI provider. Summaries appear on the page; suggestions and extraction results appear in the extension.

StoryLens also needs access to https://www.google-analytics.com/* to send feature usage events from the extension when analytics credentials are configured and the user has not turned analytics off in General settings. These events include a random client ID, extension and session information, and—for a detected novel page—the reading site hostname. They exclude page text, full URLs, glossary content, and account details.
