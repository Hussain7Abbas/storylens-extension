# Extension instructions

Follow [shared repository rules](../../AGENTS.md). This submodule is the WXT browser extension for Chrome and Firefox. See the [extension guide](../../docs/extension.md) for its architecture and behavior.

## Structure and conventions

- `src/entrypoints/background/` owns service worker messaging, API proxying, and sync alarms. `src/entrypoints/content/` handles page detection, highlighting, and the novel-site popup launcher. `popup/`, `popup.home/`, `popup.settings/`, and `options/` supply React UI entry points and screens. `website-bridge.content.ts` shares the session with the website's account pages.
- Account UI (sign-in, registration, profile, password) belongs on the website, not in extension pages, because password managers cannot fill `chrome-extension://` forms. `src/lib/website/` holds the website URL (`WXT_WEBSITE_URL`) and the bridge protocol, which must match the website's `src/lib/account/bridge.ts`. Sync recovery opens `/{locale}/profile/login/?reauth=1` to renew an expired reader session even when the website is already signed in; ordinary account-switch links use `/{locale}/profile/login/`. Account pages automatically replace a confirmed invalid bearer session with the signed-in website account even when the cached account ID differs; valid different accounts still require a choice. The bridge uses a hostname-only match pattern because WXT’s matcher rejects ports; before adding any listeners or reading storage, `isWebsiteOrigin()` must reject every origin other than the configured website, including other localhost ports. Only the bridge may expose account sessions to website pages.
- `src/lib/desktop-client/` owns local AI transport, in-page summaries (`page-summary.ts`), keyword suggestion prompts and parsing (`keyword-suggestion.ts`), chapter extraction (`chapter-extraction.ts`, whose answer may suggest a parent name and `alias`/`version` relation that the extraction view preselects and highlights), selector prompts and validation (`selector-detection.ts`) with its desktop request in `selector-detection-runner.ts`, character image prompts (`character-image.ts`) and shared cancellable image transport/file decoding (`character-image-job.ts`), novel-context research (`novel-context.ts`, with pure prompt helpers in `novel-context-prompt.ts`), the shared AI instruction types and bundled fallback templates (`ai-prompts.ts`), with central fetching/cache in `shared-ai-prompts.ts` (`storylens-shared-ai-prompts`), and the shared settings readers (`settings.ts`, `storylens-desktop-client`). Keep this separate from the generated backend API client; background handles the network requests, while **Settings → AI** (`popup.settings/ai-tab.tsx`) gets model/effort choices from the client's capabilities response. Every desktop AI request carries the selected extension language as `responseLanguage`. The client runs two jobs at a time and refuses more with `BUSY`; `runDesktopJob` retries those every 2 s for up to 15 minutes (`retryWhileBusy` in `job-stream.ts`, with the NDJSON reader, free of extension APIs), each try with its own time limit, so parallel tabs queue instead of failing. Selector detection uses the selected Cloud or Desktop source, sends a bounded page outline and URL, and validates the result on the page; a correction shares its action ID. New client code never calls the deprecated raw-HTML backend route or silently switches sources. `shareAccountSession()` posts the API URL and session token (or `null` when signed out) to the client's `/AccountSession` after each successful capabilities load and whenever `storylens-auth` changes, best-effort so older clients keep working; the desktop wiki crawler uses it. `executeAiPrompt` and `generateAiImage` accept Story Lens senders in a tab (content scripts and the launcher's popup iframe, keyed by tab so closing it cancels them) and Story Lens extension pages without a tab (the toolbar popup, sharing one owner key); reject anything else.
- The stored user (`storylens-auth`) carries `isGuest`, `role` and `permissions`. Gate UI through `userAccessAtom`, `useCanMutate()` and `useIsModerator()` (guest, reader, moderator = holds `user:moderate`), never raw role slugs; the API enforces the real permissions. `useCanMutateKeywords()`/`useCanMutateReplacements()` mean "may create"; gate edits and deletes of a row through the per-row rules in `src/lib/auth/permissions.ts` (keywords and replacements: creator or moderator; aliases and versions: their own creator, the parent keyword's creator or a moderator, decision D12), which `enqueue` also enforces. `useAuthInit` refreshes the user from `/api/user/auth/me` on open, and reloads it by token when a stored session no longer parses.
- `src/components/`, `src/hooks/`, `src/store/`, and `src/utils/` hold reusable UI, hooks, Jotai atoms, and utilities. Keep related components and styles together; use Mantine components and `@mantine/form` for existing form flows.
- Category/nature inputs in keyword, alias and version forms share `components/lookup-select.tsx`. `utils/lookup-options.ts` filters invalid IDs/names and duplicate IDs without changing cached rows; a missing selected lookup stays visible and is never implicitly cleared. Keep the error boundary around the selector alone: a render/effect failure switches it to `NativeSelect`, preserving the parent form, dirty state, picked images and AI work. The fallback retains required/error/clear semantics. `popup/render.tsx` also wraps the app in a last-resort error boundary; its bilingual `error-fallback.tsx` uses native elements so it works without Mantine/i18n providers, and reload is explicit with an unsaved-work warning. These boundaries contain React rendering failures, not browser process crashes or asynchronous/event-handler exceptions. Keep Mantine core/form/hooks aligned (currently 8.3.3, including upstream dropdown positioning fixes).
- Coloring keyword groups always sort by the parent keyword's `createdAt`, newest first, including on popup open and when searching. Keep aliases and chapter versions nested under their keyword; edits do not change the group's position.
- Character image fields (keywords, aliases and versions) use `components/image-upload.tsx` and its CSS module: a 100px drop area with a keyboard-accessible native picker, centered ImageUp icon, hover/focus and accepted/rejected drag borders, nested drag tracking and an independent delete button. Keep preview rendering below the AI prompt controls. Accept one image up to `MAX_IMAGE_BYTES` from `lib/image-upload.ts` (also re-exported by the outbox); invalid selections preserve the current image. Deleting clears both the file and `imageId` to `null`, hides the saved preview, and saves that clear through the existing offline change set. Use theme tokens and logical CSS properties; filenames never enter analytics.
- Settings tabs use content-sized flex bases (`flex: 1 0 auto`) and wrap onto another row when needed, so English labels remain separate at popup widths; preserve Mantine tab keyboard behavior and RTL order.
- Numeric levels in Settings (tooltip font size, night light level) use `components/level-slider.tsx`, a labelled Mantine `Slider` that shows the value and both ends of the range; use it rather than a `NumberInput` for any new level. Pass the selected locale's direction so its `DirectionProvider` and track use the same direction for pointer and arrow-key input. The tooltip font size (`storylens-font-size`) runs from 18 to 42 px with a 24 px default (`src/lib/font-size.ts`, no React); `fontSizeAtom` and `setTooltipFontSize()` pass it through `parseFontSize()`, which returns the default for anything outside the range, and the `content.css` fallback matches the default.
- Visual identity follows the website design system (`apps/website/design-system/MASTER.md`). Mantine tokens live in `src/styles/theme.ts` (colors, fonts, radius, shadows, `cssVariablesResolver`) and `src/styles/global.css` (self-hosted fonts, Arabic font swap, focus ring). Use the Ink & Iris `brand` primary (omit `color` for primary actions), neutral utility icons, `sage` for success, and Mantine's red/orange for errors and warnings; do not hard-code hex colors in components. Brand filled text goes through `--sl-on-brand` because the night fill is pale iris. `src/styles/palette.ts` supplies both Mantine and the isolated content surfaces (`contentThemeCss`); content tooltip CSS mirrors these values. Inter supplies all extension UI/headings; IBM Plex Sans Arabic supplies Arabic. Use Lucide (`lucide-react` for React, named `lucide` nodes for the launcher) at 1.75 stroke weight. Reader-defined keyword/category/nature colors are independent and must stay unchanged. The selected brand mark is Lensbook (option 2), sourced from `docs/branding/logo/option 2 - choosen.png` in the umbrella. `src/assets/icon.png` is the normalized 1024px master; WXT auto-icons exports 16/32/48/64/128/256/512px. Regenerate through `node docs/branding/scripts/export.cjs` from the umbrella root.
- Use `@/` for source imports. WXT entry points and framework configs may need default exports. `wxt.config.ts` sets `imports: false`, so import WXT helpers explicitly from `#imports` or WXT modules as the surrounding file does.
- React UI uses React Router, TanStack Query, Jotai, and i18next. Keep user-visible strings localized. `bun run i18n:parse` writes extracted messages to `public/locales/`; browser manifest messages live in `public/_locales/`.
- Initialize `localeAtom` from saved localStorage on the first read (`getOnInit: true`): popup mount mirrors it to extension storage, so a temporary English default would trigger the page's language refresh. In `processDetectedNovel`, preserve existing markup while loading data and waiting for the content root; only the latest request for the same page URL may remove and replace it, synchronously. Failed or missing data must not strip existing highlights.
- Content-script tooltip text is translated through `tt()` in `src/utils/keyword-tooltip.ts`. Use `getLocalizedName()` for category/nature locale pairs there. Content scripts read locale from `browser.storage.local` (`storylens-locale`), not page `localStorage`. Tooltip details use a fixed 420 px width capped to the viewport with 8 px side margins; keep all text wrappable, including long names, metadata, tab labels and inline edit buttons, and constrain images to the available width.
- Image resolution lives in `src/utils/resolve-keyword-version.ts` and is shared by the page tooltip, page highlighting and the popup lists: no entry that has an image anywhere is shown without one. Highlighting and popup list inheritance use the alias's own image (regardless of `overrideStyle`), then its keyword's — the version in effect for the chapter, then the **latest** other version that has an image (`latestVersionWithImage`), then the base version. `resolveKeywordImage()` returns that keyword image for rows that inherit it; `resolveImageInfo` keeps the provenance of every image it replaced, including empty steps, for the tooltip's show-more. Nullable style fields use alias values first, then the newest applicable version with a value, then earlier versions/base. The legacy `overrideStyle` flag does not lower alias field priority. Overlapping chapter ranges select the greatest starting chapter, independently of API array order; gaps retain the nearest earlier version. Alias and version rows (tooltip panels and `coloring-cards.tsx`) show a thumbnail of their own image, or the inherited one dimmed like the other inherited values; a row's own-image badge is only the pending-upload one. Wrap every tooltip image, thumbnails included, in `buildImageButton()` so it opens `src/utils/image-modal.ts` (a top-layer `<dialog>` sized by the image, styled in `content.css`, closed with the tooltip portal). The full-size viewer keeps a real, interactive `<img>` with its original URL and native dragging/context menu; scoped capture listeners prevent site handlers from blocking image actions without cancelling browser defaults, and are removed when it closes. Tooltip **Edit** buttons come from `buildEditButton()` and are gated by the per-row rules in `src/lib/auth/permissions.ts` against the stored user (`setTooltipUser`, fed from `storylens-auth` in `content/main.ts`). `setPagePopupLauncher` registers `onEdit` through `setTooltipActions` only while the launcher exists (the image-view tracker is always registered); it opens `popup.html?edit=keyword|alias|version&id=…&parentId=…&novelId=…`, and `coloring-tab.tsx` re-checks the same rules before opening the form. A form request in the popup URL (`edit`, or `create` from a text pick) is handled once: `consumeRequest()` removes its parameters when the form opens, because the kept popup outlives the Coloring tab and a remount (Settings and back) would otherwise reopen it.
- **Settings → Appearance → Show tooltip** selects `hover` (On hover) or `click` (On click, the default), persisted as `storylens-tooltip-trigger`. Keep the key/type/parser in `src/lib/tooltip-trigger.ts` free of React. The popup mirrors the saved preference to extension storage; content scripts load it and react to changes without re-highlighting. Changing the trigger dismisses any open tooltip. Click mode stays open across pointer movement and closes on the same keyword, an outside click or Escape; Enter/Space also toggles a focused keyword. Hover mode retains the shared hover group and delayed dismissal. Suppress both modes while the page picker is active.
- Opening a keyword tooltip shows a floating action box (`buildHoverActions()`, `.storylens-keyword-hover-actions`) attached to the tooltip on the side nearest the word: below an above-word tooltip, above a below-word tooltip. Never separate the boxes with the word. The tabs sit at that same edge, outside the scrolling details, with keyboard arrows/Home/End and ARIA selection. Placement bounds both boxes 8 px inside the viewport and reserves visible tabs/details before constraining the scrollable action box. Ignore scroll events from either scrolling box when repositioning, preserve detail scroll offset, and remeasure on font, image, tab and viewport changes. The action container has no background, border or shadow; each button carries its own surface and shadow as a separate floating island. Keep the transparent container and row gaps pointer-active so moving between buttons stays inside the shared hover group. **Edit** remains above **Generate image with AI**, gated by the existing row edit rules and launcher callbacks. **Add alias** and **Add version** open parent-scoped create forms; the sparkle beside Add alias starts the page picker and fills the alias form's name. **Add replacement** and its sparkle pick a source word/phrase and immediately enqueue a FULL replacement with the canonical keyword as To, without opening a form. Creation uses `canCreate`, independently of keyword ownership. Direct replacement picks require trusted button and pointer events so the novel page cannot synthesize a save. The launcher's guarded picker suppresses tooltip hovers, rejects extension/control markup and text longer than 512 characters, and clears on Escape, navigation, close or disposal. The typed `createPageReplacement` background message goes through `lib/offline/page-replacement.ts`, validates the extension sender/top frame/tab novel and input, derives To from the account's local keyword view and current stored locale, then uses `enqueue` and directly asks that reading tab to refresh; the normal sync kick sends the saved mutation later. Keep its success/error notices localized and show the saved-but-refresh-failed state honestly. Image generation opens `popup.html?edit=keyword&…&generate=image` and saves through the existing upload-on-save path. The form exposes saved prompts and manual prompt entry even when `character_image` is unavailable, and only sends an image request after checking availability and confirming extraction when the prompt is empty.
- Tooltip **Info** uses `resolveTooltipInfo`: alias values have priority regardless of `overrideStyle`; missing description/category/nature inherit independently from newest applicable to oldest version in the selected language. The alias name falls back to the keyword name in that language. Images use the alias image first, then the active version, latest other version with an image and base. The same inheritance applies to highlights, popup alias cards and tooltip alias rows. **Original** remains the base keyword’s information, shown for aliases and distinct active versions. Keep provenance collapsed for Info text fields and retain the image provenance chain.
- The page popup launcher reuses the generated logo icon and saves its position in `browser.storage.local` (`storylens-page-launcher-position`), shared across sites. The General settings Show/Hide preference uses `storylens-page-popup-visible` and updates content scripts immediately. The launcher tucks to the nearest edge within 10 px, leaving 3 px visible, and reveals on pointer proximity or focus. A newly created launcher (page load, or Show turned on) stays untucked for 3 s before it tucks. Clamp restored/dragged positions and popup geometry on render and resize; the popup detects the launcher iframe (`window.parent !== window`) and fills it (`html[data-embedded]`) instead of the fixed toolbar size, so popup content must use fluid widths rather than `24rem`; do not use the site's local storage for extension preferences.
- Closing the launcher popup hides its iframe; it does not remove it, so the open tab, search, form and running AI request survive until the reader opens it again. Do not remove the frame on close. The launcher keeps up to 6 popup **tabs** (`PopupTab` in `page-popup-launcher.ts`), each a separate popup frame with its own form and AI requests, so several characters and images can be generated at once; the panel shows one (`active`, which the button opens) and the others stay hidden. Every message, request and answer below is per tab, matched by the frame's window. The popup and the launcher talk through `src/lib/launcher-frame/` (`messages.ts` is free of React because the content script imports it). Every form calls `useLauncherWork({ dirty })` with its real unsaved changes (`form.isDirty()`, a picked or generated image) and every popup AI request calls it with `working`/`failed`; a running request counts as unsaved work. Values a form loads by itself go through `loadFormValues()` (`src/utils/form-baseline.ts`), which makes them the baseline only while the reader has not edited the form, and a late automatic value must not replace a field the reader already changed. The `storylens-popup-state` messages arrive late, so they drive only the button's `#status` dot: a request running in an out-of-sight popup (`working`) and its result (`ready`, `failed`) until the popup is opened, with the same text in the button label. **Never decide from that state that a popup can be replaced.** The launcher asks (`storylens-popup-request`) and the popup answers from its state at that moment (`connectLauncherFrame`, started in `popup/render.tsx` for the main popup only): for a requested form (selection create, tooltip **Edit**) the shown tab without unsaved work loads the new query itself in the same frame, and one with unsaved work answers `kept`, and the form opens in a new tab (a shown tab whose late state already says it holds work gets a new tab without being asked; at the limit the `tooManyTabs` notice shows instead). Tabs out of sight are asked (`reload: false`) whether they can go when the panel closes, another tab is shown, or their state says they hold nothing, and removed only after answering that they hold nothing; a tab with an AI task the reader has not looked at is not asked. After an in-site navigation (`pagePopupLauncherNavigated`) every tab is out of date: the launcher removes each once it answered that it holds nothing while out of sight, and asks again each time a kept, out-of-date tab is closed. A frame that is still loading gets the request when it posts `storylens-popup-ready`; only a frame that never announced itself within 5 s, and `dispose()`, are removed without an answer. The launcher accepts popup messages only from its popup frame's window and the extension origin. The text-pick chooser uses its own frame beside the kept popup. The novel site is the popup's parent window too and can send launcher messages: a request only reloads a popup that holds nothing, and `storylens-popup-shown` (`useLauncherShown`) may only trigger cheap, rate-limited refreshes (the stale sync runs at most once per 30 s).
- Every AI request in a launcher frame calls `useAiTask({ operation, subject, working, failed, holding })` (`src/lib/launcher-frame/use-ai-task.ts`) next to `useLauncherWork`, so the launcher shows it on its tab's card under the button (`#tasks`: spinner, then green check or red cross, text "{subject} - {operation}" localized in the launcher's `labels()`). Each card is a tab (one per `PopupTab`, all listed once there are two, the current one marked `aria-current`) and opens it; a tab without AI tasks is named after its form (`forms` labels) or "Story Lens". The popup announces a random `key` in its `storylens-popup-ready` message (`launcherFrameKey()`), and its task reports carry it as `frame`, which is how the launcher matches tasks to tabs. Frames report through the background (`reportAiTask` → `aiTaskUpdated` to the tab's top frame) so names never reach the novel site's window; content-script requests (the summary) apply to `pageAiTasks` (`ai-tasks.ts`, no React) directly. A done task holds its result until `holding` turns false or the component unmounts, and while it does the hook reports the popup as dirty, so the tab is kept and the next form opens in a new tab; failed tasks hold nothing. `useKeywordSuggestion` returns its suggestion state, optional image state and `clear()`; `ColoringTab` clears it when the last form is saved or dismissed, releasing the task even though the tab stays mounted. The launcher keeps a `beforeunload` listener only while `pageAiTasks.unsaved()` or the popup reports dirty work, so pages keep their back/forward cache otherwise. Drop a frame's tasks when its frame goes (`discardTab`, a tab reload, `clearChapterExtraction`), including an iframe that reloads itself: a ready message with a different key drops the previous key's tasks before replacing it; a repeated ready message with the same key preserves them. Add new AI operations to `AI_TASK_OPERATIONS` and both label sets.
- The launcher's hover row has four 44px actions (`select`, `summarize`, `extract`, `night-light`). `night-light` toggles a yellow layer over the page (`src/lib/night-light.ts`, no React): it swaps the Lucide `Moon`/`Sun` icon and its label with the state and keeps the row open. The on/off state (`storylens-night-light`) and the level (`storylens-night-light-level`, 10 to 80 percent, set in **Settings → Appearance** through `nightLightLevelAtom` and mirrored to `browser.storage.local` in `popup/App.tsx`) are shared across sites and tabs; read the level through `parseNightLightLevel()`, which clamps it. The layer is a separate element after `<body>`, not inside the launcher's shadow root, because `mix-blend-mode: multiply` only blends with the page from the root stacking context; keep it click-through and marked `data-storylens-skip`. It exists only while the launcher does: `dispose()` removes it without changing the saved state.
- The page picker lives only on the launcher, with one `+` for picking. After a word/phrase is selected, embed `popup.html?view=selection` above its range, clamped to the viewport. `popup/selection-view.tsx` offers localized Keyword/Alias/Version icon buttons and adjacent **Use AI** and **Generate Image** switches, both off by default. Image generation is enabled only with AI on and the `character_image` feature available; turning AI off clears the image choice. Carry the optional boolean `generateImage` only from the trusted chooser, translate it to `generate=image` only with AI context, and consume it with the create request. `useKeywordSuggestion` prepares prompts/novel context once, then runs the suggestion and image concurrently with independent results, errors, cancellation and launcher tasks. Wait for both before opening the form; carry a successful image into its file state for upload on save even if the suggestion failed. Optional context research must preserve the combined action budget. Unavailable AI explains the selected source restriction and continues manually. Alias and Version require `components/parent-keyword-select.tsx`, a debounced fuzzy dropdown backed by `useNovelKeywords` (the novel's local view). The parent is scoped to the selected novel and clears when the novel changes. Only trust selection messages from the actual iframe window and extension origin; dispose the listener on close. The chooser reports its measured height, and the launcher retains the range anchor while resizing. Selected text, kind, novel and parent IDs seed the full popup through query parameters; page context belongs only in `aiContext` (`encodeKeywordContext`). With AI on, `openInBackground` loads the form in a new hidden `PopupTab` with `background` set instead of showing the panel: its card shows a spinner from the start, `collectTabs` never asks it, and `finishBackground` opens it once its AI tasks or working state end (or 8 s pass without a request starting), only while the panel, chooser and picker are all closed; otherwise it stays a finished card. Showing the tab by any path clears `background`, so it never opens itself later. At the tab limit the request falls back to `open()`. Keep selection listeners disposable and Escape cancellable; every exit path must call `setPageSelectionUnlocked(false)`.
- All edit/create/delete forms use `components/form-page.tsx`: a portal occupies the whole content region below the navbar while the originating page stays mounted but hidden. Navbar Back closes the form before popping a page route, preserving the active tab/search. Wrap new forms in `FormPage`; do not render them inline beside tab lists or novel controls. Use localized tooltips on action buttons, including text actions, with existing explanatory AI-disabled tooltips retained.
- Lens prices use `components/lens/lens-price.tsx` (`LensPrice`, `useLensLabel`) and `components/lens/lens-coin.tsx`; the launcher (no React) uses `LENS_COIN_MONO` and `formatLenses` from `src/lib/lens-coin.ts`. Labels come from i18next plurals (`lens.count_*`, all six Arabic forms) with Latin digits; never format a lens amount by hand.
- Every AI action outside Settings uses feature-keyed `aiAvailability()` / `useAiAvailability()` from `src/lib/ai-source/`; reserve `isAiConfigured()` for Desktop-only checks. `parseAiSource()` preserves configured pairings as Desktop when the source is unset. Text uses `storylens-ai-source`; images use `storylens-ai-image-source`, falling back to the legacy shared choice until the first provider change. Use `featureAiSource()` and `aiState(feature)` for routing and feature-specific prices/availability. `saveAiSource()` preserves the current image choice when text changes. Desktop images need pairing independently of text model selection and always send Codex/default effort; optional novel research follows the text provider and reserves only the Cloud actions’ budgets. `executeLocalizedPrompt()` requires a feature and keeps one action ID for attempts 1 and 2. Cloud corrections are free; a failed correction keeps a usable first result. Cloud transport lives in `src/lib/cloud-ai/`, with serializable reply unions, bearer/version/language headers, bounded responses, owner-scoped aborts and absolute job limits. Cloud summaries send cleaned visible text, Desktop cleaned HTML; never send forms or silently truncate an oversized Cloud prompt. React disabled AI actions use `data-disabled` inside a Tooltip, preserving hover access. Build every AI prompt with `languageRule()` and run popup prompts through `executeLocalizedPrompt()`. ## API and offline data

`orval.config.ts` generates React Query endpoints and schemas into `src/api/generated/` from the running backend's `/openapi.json`. It generates only the reader API (`/api/user`): dashboard `Admin: …` tags are excluded, `operationName` drops the `ApiUser` prefix so names stay stable, and `clean` removes stale files. Hand-written Axios calls must also use `/api/user/...` paths; Better Auth's `/auth/*` is only for the website's OAuth flow. Import generated types and functions from those paths; do not edit generated files manually. The generated output is committed because CI typechecks and builds without a running backend; after backend API changes, rerun `make orval` and commit the regenerated files. The custom Axios client is `src/api/axios-instance.ts`; `src/api/client-compat.ts` sends `X-Client-Version` on every request, handles 426 Upgrade Required with a store update check, and warns in development about deprecated endpoints. Send all API calls through `axiosInstance` so they carry the version. Tolerate unknown response fields and enum values, and never adopt an endpoint or field whose generated code is `@deprecated` (see [API and data compatibility](../../docs/compatibility.md)). Use query hooks in React UI and the existing direct/proxied API flow in extension contexts.

Offline data is local-first (`src/lib/offline/`, see the [extension guide](../../docs/extension.md#offline-first-engine)). The IndexedDB database `storylens` (`db.ts`, schema version 2 with an explicit migration for saved image descriptions and queued edits) holds **snapshot** tables (server rows only) and the **outbox** (`mutations`); every screen and the page read **views** (snapshot plus the account's unresolved changes, `projection.ts`). Rules:

- UI code never calls write endpoints for keywords, aliases, versions, replacements, categories or natures, and never writes snapshot tables. Writes go through `enqueue` (`outbox.ts`) via the hooks in `hooks.ts`; only `sync/transport.ts` calls write endpoints, and only pulls and push outcomes (`snapshot.ts`, inside the runner's `storylens-sync` lock) write snapshots. Online-only calls (novels, slugs, website selectors, chapter biases, novel context) end with `requestNovelRefresh` or a catalogue pull instead of writing Dexie.
- IDs are client UUIDs (`ids.ts`); there are no temporary IDs or dirty flags. Every outbox change and the reads it depends on happen in one Dexie transaction.
- Forms send changes, not snapshots: build them with `form-changes.ts` and pass `seen` (the initial values of the changed fields) and `seenUpdatedAt` (the row's `updatedAt` when the form opened); cleared optional text is `null`. Show `enqueue` refusals with `offlineErrorMessage` (`errors.ts`).
- Server rule mirrors live in `rules/validation.ts` and the projection mirrors server side effects (base version, auto-close, chain rewrite, cascades); change them together with the backend rule they cite.

Keyword and alias forms show `fuzzyMatchArabicCharacters` only for names containing Arabic letters. It defaults to `true` in the backend, offline outbox/projection and forms.
