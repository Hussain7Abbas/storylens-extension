# Extension instructions

Follow [shared repository rules](../../AGENTS.md). This submodule is the WXT browser extension for Chrome and Firefox. See the [extension guide](../../docs/extension.md) for its architecture and behavior.

## Structure and conventions

- `src/entrypoints/background/` owns service worker messaging, API proxying, and sync alarms. `src/entrypoints/content/` handles page detection, highlighting, and the novel-site popup launcher. `popup/`, `popup.home/`, `popup.settings/`, and `options/` supply React UI entry points and screens. `website-bridge.content.ts` shares the session with the website's account pages.
- Account UI (sign-in, registration, profile, password) belongs on the website, not in extension pages, because password managers cannot fill `chrome-extension://` forms. `src/lib/website/` holds the website URL (`WXT_WEBSITE_URL`) and the bridge protocol, which must match the website's `src/lib/account/bridge.ts`. Only the bridge script may run on the website origin; never match it more broadly, since it returns the session token to the page.
- `src/lib/desktop-client/` owns local AI transport, in-page summaries (`page-summary.ts`), keyword suggestion prompts and parsing (`keyword-suggestion.ts`), chapter extraction (`chapter-extraction.ts`, whose answer may suggest a parent name and `alias`/`version` relation that the extraction view preselects and highlights), selector prompts and validation (`selector-detection.ts`) with its desktop request in `selector-detection-runner.ts`, character image prompts (`character-image.ts`), novel-context research (`novel-context.ts`, with pure prompt helpers in `novel-context-prompt.ts`), the reader's AI prompts and their seeded defaults (`ai-prompts.ts`, stored in `storylens-ai-prompts`), and the shared settings readers (`settings.ts`, `storylens-desktop-client`). Keep this separate from the generated backend API client; background handles the network requests, while **Settings → AI** (`popup.settings/ai-tab.tsx`) gets model/effort choices from the client's capabilities response. Every desktop AI request carries the selected extension language as `responseLanguage`. The client runs two jobs at a time and refuses more with `BUSY`; `runDesktopJob` retries those every 2 s for up to 15 minutes (`retryWhileBusy` in `job-stream.ts`, with the NDJSON reader, free of extension APIs), each try with its own time limit, so parallel tabs queue instead of failing. Selector detection prefers the configured desktop provider, sends a bounded page outline and URL, validates the result on the page, and never silently falls back to OpenRouter after a desktop failure. With no configured desktop AI it uses the existing backend OpenRouter route. `shareAccountSession()` posts the API URL and session token (or `null` when signed out) to the client's `/AccountSession` after each successful capabilities load and whenever `storylens-auth` changes, best-effort so older clients keep working; the desktop wiki crawler uses it. `executeDesktopPrompt` and `generateDesktopImage` accept Story Lens senders in a tab (content scripts and the launcher's popup iframe, keyed by tab so closing it cancels them) and Story Lens extension pages without a tab (the toolbar popup, sharing one owner key); reject anything else.
- The stored user (`storylens-auth`) carries `isGuest`, `role` and `permissions`. Gate UI through `userAccessAtom`, `useCanMutate()` and `useIsModerator()` (guest, reader, moderator = holds `user:moderate`), never raw role slugs; the API enforces the real permissions. `useCanMutateKeywords()`/`useCanMutateReplacements()` mean "may create"; gate edits and deletes of a row through the per-row rules in `src/lib/auth/permissions.ts` (keywords and replacements: creator or moderator; aliases and versions: their own creator, the parent keyword's creator or a moderator, decision D12), which `enqueue` also enforces. `useAuthInit` refreshes the user from `/api/user/auth/me` on open, and reloads it by token when a stored session no longer parses.
- `src/components/`, `src/hooks/`, `src/store/`, and `src/utils/` hold reusable UI, hooks, Jotai atoms, and utilities. Keep related components and styles together; use Mantine components and `@mantine/form` for existing form flows.
- Numeric levels in Settings (tooltip font size, night light level) use `components/level-slider.tsx`, a labelled Mantine `Slider` that shows the value and both ends of the range; use it rather than a `NumberInput` for any new level. Pass the selected locale's direction so its `DirectionProvider` and track use the same direction for pointer and arrow-key input. The tooltip font size (`storylens-font-size`) runs from 18 to 42 px with a 24 px default (`src/lib/font-size.ts`, no React); `fontSizeAtom` and `setTooltipFontSize()` pass it through `parseFontSize()`, which returns the default for anything outside the range, and the `content.css` fallback matches the default.
- Visual identity follows the website design system (`apps/website/design-system/MASTER.md`). Mantine tokens live in `src/styles/theme.ts` (colors, fonts, radius, shadows, `cssVariablesResolver`) and `src/styles/global.css` (self-hosted fonts, Arabic font swap, focus ring). Use the Ink & Iris `brand` primary (omit `color` for primary actions), neutral utility icons, `sage` for success, and Mantine's red/orange for errors and warnings; do not hard-code hex colors in components. Brand filled text goes through `--sl-on-brand` because the night fill is pale iris. `src/styles/palette.ts` supplies both Mantine and the isolated content surfaces (`contentThemeCss`); content tooltip CSS mirrors these values. Inter supplies all extension UI/headings; IBM Plex Sans Arabic supplies Arabic. Use Lucide (`lucide-react` for React, named `lucide` nodes for the launcher) at 1.75 stroke weight. Reader-defined keyword/category/nature colors are independent and must stay unchanged. The selected brand mark is Lensbook (option 2), sourced from `docs/branding/logo/option 2 - choosen.png` in the umbrella. `src/assets/icon.png` is the normalized 1024px master; WXT auto-icons exports 16/32/48/64/128/256/512px. Regenerate through `node docs/branding/scripts/export.cjs` from the umbrella root.
- Use `@/` for source imports. WXT entry points and framework configs may need default exports. `wxt.config.ts` sets `imports: false`, so import WXT helpers explicitly from `#imports` or WXT modules as the surrounding file does.
- React UI uses React Router, TanStack Query, Jotai, and i18next. Keep user-visible strings localized. `bun run i18n:parse` writes extracted messages to `src/i18n/messages/`; browser manifest messages live in `public/_locales/`.
- Initialize `localeAtom` from saved localStorage on the first read (`getOnInit: true`): popup mount mirrors it to extension storage, so a temporary English default would trigger the page's language refresh. In `processDetectedNovel`, preserve existing markup while loading data and waiting for the content root; only the latest request for the same page URL may remove and replace it, synchronously. Failed or missing data must not strip existing highlights.
- Content-script tooltip text is translated through `tt()` in `src/utils/keyword-tooltip.ts`. Use `getLocalizedName()` for category/nature locale pairs there. Content scripts read locale from `browser.storage.local` (`storylens-locale`), not page `localStorage`.
- Tooltip image resolution lives in `src/utils/resolve-keyword-version.ts`: an alias shows its own image regardless of `overrideStyle` and falls back to its keyword's (active version, then base) when it has no uploaded image; style fields keep the override chain. Wrap every tooltip image in `buildImageButton()` so it opens `src/utils/image-modal.ts` (a top-layer `<dialog>` sized by the image, styled in `content.css`, closed with the tooltip portal). Tooltip **Edit** buttons come from `buildEditButton()` and are gated by the per-row rules in `src/lib/auth/permissions.ts` against the stored user (`setTooltipUser`, fed from `storylens-auth` in `content/main.ts`). `setPagePopupLauncher` registers `onEdit` through `setTooltipActions` only while the launcher exists (the image-view tracker is always registered); it opens `popup.html?edit=keyword|alias|version&id=…&parentId=…&novelId=…`, and `coloring-tab.tsx` re-checks the same rules before opening the form. A form request in the popup URL (`edit`, or `create` from a text pick) is handled once: `consumeRequest()` removes its parameters when the form opens, because the kept popup outlives the Coloring tab and a remount (Settings and back) would otherwise reopen it.
- The page popup launcher reuses the generated logo icon and saves its position in `browser.storage.local` (`storylens-page-launcher-position`), shared across sites. The General settings Show/Hide preference uses `storylens-page-popup-visible` and updates content scripts immediately. The launcher tucks to the nearest edge within 10 px, leaving 3 px visible, and reveals on pointer proximity or focus. A newly created launcher (page load, or Show turned on) stays untucked for 3 s before it tucks. Clamp restored/dragged positions and popup geometry on render and resize; the popup detects the launcher iframe (`window.parent !== window`) and fills it (`html[data-embedded]`) instead of the fixed toolbar size, so popup content must use fluid widths rather than `24rem`; do not use the site's local storage for extension preferences.
- Closing the launcher popup hides its iframe; it does not remove it, so the open tab, search, form and running AI request survive until the reader opens it again. Do not remove the frame on close. The launcher keeps up to 6 popup **tabs** (`PopupTab` in `page-popup-launcher.ts`), each a separate popup frame with its own form and AI requests, so several characters and images can be generated at once; the panel shows one (`active`, which the button opens) and the others stay hidden. Every message, request and answer below is per tab, matched by the frame's window. The popup and the launcher talk through `src/lib/launcher-frame/` (`messages.ts` is free of React because the content script imports it). Every form calls `useLauncherWork({ dirty })` with its real unsaved changes (`form.isDirty()`, a picked or generated image) and every popup AI request calls it with `working`/`failed`; a running request counts as unsaved work. Values a form loads by itself go through `loadFormValues()` (`src/utils/form-baseline.ts`), which makes them the baseline only while the reader has not edited the form, and a late automatic value must not replace a field the reader already changed. The `storylens-popup-state` messages arrive late, so they drive only the button's `#status` dot: a request running in an out-of-sight popup (`working`) and its result (`ready`, `failed`) until the popup is opened, with the same text in the button label. **Never decide from that state that a popup can be replaced.** The launcher asks (`storylens-popup-request`) and the popup answers from its state at that moment (`connectLauncherFrame`, started in `popup/render.tsx` for the main popup only): for a requested form (selection create, tooltip **Edit**) the shown tab without unsaved work loads the new query itself in the same frame, and one with unsaved work answers `kept`, and the form opens in a new tab (a shown tab whose late state already says it holds work gets a new tab without being asked; at the limit the `tooManyTabs` notice shows instead). Tabs out of sight are asked (`reload: false`) whether they can go when the panel closes, another tab is shown, or their state says they hold nothing, and removed only after answering that they hold nothing; a tab with an AI task the reader has not looked at is not asked. After an in-site navigation (`pagePopupLauncherNavigated`) every tab is out of date: the launcher removes each once it answered that it holds nothing while out of sight, and asks again each time a kept, out-of-date tab is closed. A frame that is still loading gets the request when it posts `storylens-popup-ready`; only a frame that never announced itself within 5 s, and `dispose()`, are removed without an answer. The launcher accepts popup messages only from its popup frame's window and the extension origin. The text-pick chooser uses its own frame beside the kept popup. The novel site is the popup's parent window too and can send launcher messages: a request only reloads a popup that holds nothing, and `storylens-popup-shown` (`useLauncherShown`) may only trigger cheap, rate-limited refreshes (the stale sync runs at most once per 30 s).
- Every AI request in a launcher frame calls `useAiTask({ operation, subject, working, failed, holding })` (`src/lib/launcher-frame/use-ai-task.ts`) next to `useLauncherWork`, so the launcher shows it on its tab's card under the button (`#tasks`: spinner, then green check or red cross, text "{subject} - {operation}" localized in the launcher's `labels()`). Each card is a tab (one per `PopupTab`, all listed once there are two, the current one marked `aria-current`) and opens it; a tab without AI tasks is named after its form (`forms` labels) or "Story Lens". The popup announces a random `key` in its `storylens-popup-ready` message (`launcherFrameKey()`), and its task reports carry it as `frame`, which is how the launcher matches tasks to tabs. Frames report through the background (`reportAiTask` → `aiTaskUpdated` to the tab's top frame) so names never reach the novel site's window; content-script requests (the summary) apply to `pageAiTasks` (`ai-tasks.ts`, no React) directly. A done task holds its result until `holding` turns false or the component unmounts, and while it does the hook reports the popup as dirty, so the tab is kept and the next form opens in a new tab; failed tasks hold nothing. `useKeywordSuggestion` returns its state and `clear()`; `ColoringTab` clears it when the last form is saved or dismissed, releasing the task even though the tab stays mounted. The launcher keeps a `beforeunload` listener only while `pageAiTasks.unsaved()` or the popup reports dirty work, so pages keep their back/forward cache otherwise. Drop a frame's tasks when its frame goes (`discardTab`, a tab reload, `clearChapterExtraction`), including an iframe that reloads itself: a ready message with a different key drops the previous key's tasks before replacing it; a repeated ready message with the same key preserves them. Add new AI operations to `AI_TASK_OPERATIONS` and both label sets.
- The launcher's hover row has four 44px actions (`select`, `summarize`, `extract`, `night-light`). `night-light` toggles a yellow layer over the page (`src/lib/night-light.ts`, no React): it swaps the Lucide `Moon`/`Sun` icon and its label with the state and keeps the row open. The on/off state (`storylens-night-light`) and the level (`storylens-night-light-level`, 10 to 80 percent, set in **Settings → Appearance** through `nightLightLevelAtom` and mirrored to `browser.storage.local` in `popup/App.tsx`) are shared across sites and tabs; read the level through `parseNightLightLevel()`, which clamps it. The layer is a separate element after `<body>`, not inside the launcher's shadow root, because `mix-blend-mode: multiply` only blends with the page from the root stacking context; keep it click-through and marked `data-storylens-skip`. It exists only while the launcher does: `dispose()` removes it without changing the saved state.
- The page picker lives only on the launcher, with one `+` for picking. After a word/phrase is selected, embed `popup.html?view=selection` above its range, clamped to the viewport. `popup/selection-view.tsx` offers localized Keyword/Alias/Version icon buttons and an AI switch defaulting to on; unavailable AI explains `desktop.configureAi` and continues manually. Alias and Version require `components/parent-keyword-select.tsx`, a debounced fuzzy dropdown backed by `useNovelKeywords` (the novel's local view). The parent is scoped to the selected novel and clears when the novel changes. Only trust selection messages from the actual iframe window and extension origin; dispose the listener on close. The chooser reports its measured height, and the launcher retains the range anchor while resizing. Selected text, kind, novel and parent IDs seed the full popup through query parameters; page context belongs only in `aiContext` (`encodeKeywordContext`). Keep selection listeners disposable and Escape cancellable; every exit path must call `setPageSelectionUnlocked(false)`.
- All edit/create/delete forms use `components/form-page.tsx`: a portal occupies the whole content region below the navbar while the originating page stays mounted but hidden. Navbar Back closes the form before popping a page route, preserving the active tab/search. Wrap new forms in `FormPage`; do not render them inline beside tab lists or novel controls. Use localized tooltips on action buttons, including text actions, with existing explanatory AI-disabled tooltips retained.
- Every AI action outside Settings shares `isAiConfigured()` / `useAiConfigured()` (pairing token, model and effort). React disabled AI actions use `data-disabled` inside a Tooltip, preserving hover access. The chapter panel embeds `popup.html?view=extract` and only trusts messages from its own frame; chapter text uses the typed `getChapterText` message. Build every AI prompt with `languageRule()` and run popup prompts through `executeLocalizedPrompt()`. Keyword and image prompts put the reader's Settings → AI prompt first through `instructionSection()` (it has priority), then the chapter material, then `novelContextSection()`; get the context with `ensureNovelContext()`, which researches an empty context with web search and saves it, and never blocks the action when that fails. Character forms use `components/generate-image-button.tsx`, which hands the generated image to the form's file state so the existing upload-on-save sends it to image storage. `useKeywordSuggestion` prefills selected-text forms; related suggestions retain a parent note. Character and replacement lists use `fuzzyMatches` online and offline. Creation forms seed Name/From from search text, and versions seed Description because they have no name field.
- `src/lib/analytics/` sends Google Analytics 4 events through the Measurement Protocol from the background worker (MV3 forbids remote `gtag.js`). See [Analytics events](#analytics-events) for the tracking rules and event catalog.
- Biome is configured by `biome.jsonc`; package scripts `check`, `format`, and `lint` write fixes. Use the existing style and run `bun run typecheck` after implementation changes.

## API and offline data

`orval.config.ts` generates React Query endpoints and schemas into `src/api/generated/` from the running backend's `/openapi.json`. It generates only the reader API (`/api/user`): dashboard `Admin: …` tags are excluded, `operationName` drops the `ApiUser` prefix so names stay stable, and `clean` removes stale files. Hand-written Axios calls must also use `/api/user/...` paths; Better Auth's `/auth/*` is only for the website's OAuth flow. Import generated types and functions from those paths; do not edit generated files manually. The generated output is committed because CI typechecks and builds without a running backend; after backend API changes, rerun `make orval` and commit the regenerated files. The custom Axios client is `src/api/axios-instance.ts`; `src/api/client-compat.ts` sends `X-Client-Version` on every request, handles 426 Upgrade Required with a store update check, and warns in development about deprecated endpoints. Send all API calls through `axiosInstance` so they carry the version. Tolerate unknown response fields and enum values, and never adopt an endpoint or field whose generated code is `@deprecated` (see [API and data compatibility](../../docs/compatibility.md)). Use query hooks in React UI and the existing direct/proxied API flow in extension contexts.

Offline data is local-first (`src/lib/offline/`, see the [extension guide](../../docs/extension.md#offline-first-engine)). The IndexedDB database `storylens` (`db.ts`, one schema, no Dexie upgrade functions: a schema change that needs a data change gets its own, explicitly planned migration) holds **snapshot** tables (server rows only) and the **outbox** (`mutations`); every screen and the page read **views** (snapshot plus the account's unresolved changes, `projection.ts`). Rules:

- UI code never calls write endpoints for keywords, aliases, versions, replacements, categories or natures, and never writes snapshot tables. Writes go through `enqueue` (`outbox.ts`) via the hooks in `hooks.ts`; only `sync/transport.ts` calls write endpoints, and only pulls and push outcomes (`snapshot.ts`, inside the runner's `storylens-sync` lock) write snapshots. Online-only calls (novels, slugs, website selectors, chapter biases, novel context) end with `requestNovelRefresh` or a catalogue pull instead of writing Dexie.
- IDs are client UUIDs (`ids.ts`); there are no temporary IDs or dirty flags. Every outbox change and the reads it depends on happen in one Dexie transaction.
- Forms send changes, not snapshots: build them with `form-changes.ts` and pass `seen` (the initial values of the changed fields) and `seenUpdatedAt` (the row's `updatedAt` when the form opened); cleared optional text is `null`. Show `enqueue` refusals with `offlineErrorMessage` (`errors.ts`).
- Server rule mirrors live in `rules/validation.ts` and the projection mirrors server side effects (base version, auto-close, chain rewrite, cascades); change them together with the backend rule they cite.
- Content scripts never open the extension database (it would be the site's); they ask the background (`getNovelContentData`). Offline full pulls and online-only fallback use `/sync/snapshot/*` to fetch both languages and a cursor in one server snapshot; page data still reads the local view when IndexedDB is available.
- Local reads use TanStack Query `networkMode: "always"` under the `["offline", …]` key; `useOfflineInvalidation` (mounted in `popup/App.tsx`) refreshes them when another context writes. Status counts come from the outbox (`useOutbox`, `useSyncStatus`): pending, sending, needs attention (`conflict`/`rejected`) and other account; the badge and navbar follow the same model.
- Row badges come from the view's sync state through `components/sync-badge.tsx` ("Needs attention" links to the Sync status page). When IndexedDB is unavailable (`isOfflineUnavailable()`), reads fall back to the API (`fetchNovelBundle`, `fetchLookups`, `fetchNovels`) and `enqueue` throws `StorageUnavailable`.
- `upgrade-cleanup.ts` is the only code that touches 3.2.x storage (`storylens-offline`, `storylens-sync-state`), and only to delete it; remove it in the release after the offline-first release.

Novel and keyword names are translated (`nameAr`/`nameEn`; novels also `descriptionAr`/`descriptionEn`). Readers see and write only the UI language's field: use `nameIn`/`descriptionIn`/`nameFields` from `src/utils/translation.ts` and `useLanguage()` from `src/store/locale.ts`, never fall back to the other language in UI, and hide items without a name in the UI language (`namedIn`). The Axios interceptor sends the UI language as `Accept-Language` (`src/utils/stored-language.ts`), so the API filters online lists; the novel catalogue and downloads fetch both languages so local data survives a language switch, and every local read filters by language. Page highlighting matches the UI language's names (`NovelContentData.language`) and re-runs when the language changes. Aliases are named by `nameAr`/`nameEn` like keywords: forms edit the UI language's name through `nameFields`, both names are highlighted and searched (`aliasMatchNames`, one enriched entry per name in `resolve-keyword-version.ts`), and displays use `aliasDisplayName` (the UI language's name, or the alias's other name when it has only that one). Versions, replacements and chapters are not translated yet.

Keyword and alias forms show `fuzzyMatchArabicCharacters` only for names containing Arabic letters. It defaults to `true` in the backend, offline outbox/projection and forms. The page matcher treats ا/أ/إ/آ/ٱ as equivalent only for enabled Arabic terms, preserves page text, and keeps full-word behavior separate. Strict terms take priority over fuzzy terms when both could match. Keep regex capture resolution aligned with each enriched keyword or alias; replacements do not use this setting.

For a field that needs offline support, update its snapshot row type, the `enqueue` input and diff, the projection, the transport body, the form's change set, and localization as applicable. UI-only state does not need to enter the offline store.

## Analytics events

Popup and content scripts call `trackEvent()` from `src/lib/analytics/client.ts`, which forwards a typed `trackAnalyticsEvent` message; background code calls `trackAnalyticsEvent()` from `background.ts`. Do not call GA directly from UI code. Analytics is inactive unless `WXT_GA_MEASUREMENT_ID` and `WXT_GA_API_SECRET` are set at build time, users can opt out in General settings (`storylens-analytics-enabled`), and development builds post to GA's debug endpoint and log validation results.

Keep events in step with features as part of every task, without being asked:

- **Add** an event when a task adds a user-facing feature or a meaningful user action (a new screen or popup route, a new action button, a new AI or sync flow, a new setting). Track the action once, at the point it succeeds or is requested, not on every render or retry.
- **Update** an event's name or parameters when the tracked flow changes shape, and **delete** its `trackEvent()` call when the feature or action is removed. Do not leave calls for code paths that no longer exist.
- Use `snake_case` names of the form `<object>_<action>` (for example `novel_page_view`, `ai_summary_requested`); prefer GA4's recommended names (`page_view`, `login`, `sign_up`) when one fits. Keep names at most 40 characters and parameters at most 25 per event, with string, number, or boolean values.
- Only send anonymous, non-content parameters: never page text, selected text, novel or chapter titles, slugs, full URLs, keywords, prompts, emails, or account IDs. A hostname, route name, count, enum-like option, or boolean is fine.
- Update the catalog below in the same change as every added, renamed, or removed event. It must match the code; check with `rg "trackEvent\(|trackAnalyticsEvent\(" src`.

## Commands

From this directory: `bun run dev`, `bun run dev:firefox`, `bun run build`, `bun run build:firefox`, `bun run zip`, `bun run zip:firefox`, `bun run typecheck`, `bun run test` (fake browser, `fake-indexeddb` and an in-memory API following the sync contract, in `test/helpers/`; `test/ui/` renders components under happy-dom, registered once in that file and with `globalThis.browser`/`chrome` stubbed for the messaging polyfill; also `make test`, root `make test` and the publish workflow), `bun run orval`, and `bun run i18n:parse`. Translations live in `public/locales/{en,ar}.json`. `make release-chrome` builds the store zip and `make submit-chrome` uploads the current `package.json` version's zip through `wxt submit`. `.github/workflows/publish-chrome.yml` runs both on `v*` tags (the tag must match `package.json`) or by manual dispatch, then dispatches `extension-submitted` to the backend repo, whose workflow sets `Review_Version`. Bump the version before each release. Run the backend first for Orval and ensure `WXT_API_URL` points to it; the checked-in development example uses port 7001 while the backend default is 3000.

Keep this file and the [extension guide](../../docs/extension.md) current when extension rules, entry points, commands, or behavior change, following the root maintenance rule.

General settings exposes locale-matched website, privacy, and terms links on `storylens.iscoded.com`; keep these links and public locale strings synchronized.
